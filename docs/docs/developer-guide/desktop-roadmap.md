# Telos Desktop roadmap (remember this)

When a later session asks **what is still pending** for the **Linux session stack**, the answer is **none of P0–P4, Helix, Surface, or Wayland W0–W3**. Spec: [telos-wayland-shell.md](./telos-wayland-shell.md). `:app:app` still must not depend on `:desktop-linux`. `:app:ui` hosts `:ui-kmp` screens. Spec: [Telos Helix](./telos-helix.md).

**Cross-platform binaries (GitHub):** Linux + Windows UberJars are the current ship targets (see `build-desktop-binaries.yml`). macOS Intel/ARM ships only after those play correctly. Branding is **Telos Desktop** (module path remains `:desktop-linux`).

| Phase | Status | Scope |
| --- | --- | --- |
| **P0** | In tree | `telos-session` → vault CLI unlock → **labwc** compositor → Telos Compose shell (`--session`). Host apps are normal labwc windows. x64 UberJar. |
| **P1** | In tree | Session **HOME is the vault mount**. nftables `inet telos_session` default-drop + `~/.config/telos/net-allow.txt`. Optional FIDO2 mix-in via `fido2-token` / `fido2-assert`. Panic unmount unchanged. Arm64 jar = same Gradle task on an aarch64 host. Linux only. |
| **P2** | In tree | Search (apps, files, calculator, Flatpak), Media libraries + MPRIS, Store install/uninstall/update, archives, Files workspaces and cloud. Opt-in vault-local file name index (`VaultFileNameIndex`, off by default). Remaining P2 polish only if gaps appear. |

## Virtual OS phases (VOS-1 … VOS-6)

These sit **on top of** P0–W3 (still in tree). They describe the Telos Desktop **Virtual OS** roadmap, not Android launcher work.

| Phase | Status | Scope |
| --- | --- | --- |
| **VOS-1** | **Partial (in tree)** | Vault profile folders under config `profiles/` (portable session layout when Portable Data is active); active name from `profile.active` in vault `desktop.properties` plus a plain marker (no secrets in properties). **Profile-scoped appearance:** `profiles/<name>/desktop.properties` may override `theme.intensity` / `theme.accent` / `icons.theme` / `cursor.theme` (overlay then global; no host HOME writes in Portable Data); reload on profile switch. **Panic mute:** Super+Shift+P / Control Center forces Quiet Ops and hides neon chrome; session flag + optional `theme.panicMute` — never touches nftables/kill-switch. **PortableData / PortableVault** boot paths on Windows/macOS with `PortableEnvironmentIsolator` + `PortableTraceGuard` (TMPDIR, XDG_*, no host profile writes). **Multi-vault / profile switch UI** in pre-boot and Helix Settings (`VaultProfileSwitchPanel`: list / create / switch named profiles and portable roots). Full multi-host productization and lock-gated remount remain future work. |
| **VOS-2** | **Partial (in tree)** | **Network MVP:** `DesktopNetworkController` + multi-tab Telos Network app (Status, DNS, session nftables allowlist, Apps routing table, WireGuard via host `wg-quick`/`wg`, Tor SOCKS 9050, encrypted DNS preference + Linux `resolvectl` when available). **Kill-switch:** preference in `~/.config/telos/kill-switch.txt`; on Linux keeps `inet telos_session` default-drop enforced (refuse clear, re-apply after tunnel stop) with Enforced/Failed/PreferenceOnly UI status; Windows/macOS store preference only (honest not-applied). **Per-app routing:** `~/.config/telos/app-routing.txt` (`desktop-id`/`package` → allow/deny/vpn) persisted + editable; on Linux `DesktopFileLauncher` consults the table (`appRoutingEnforced()` when deny rules exist): **deny blocks launch**, **vpn** sets `TELOS_APP_ROUTE=vpn` best-effort (no fake netns). Process-level nftables owner/cgroup routing is intentionally not applied (keeps session kill-switch intact). **DNS filters:** vault `dns-block.txt` / `dns-allow.txt` + optional NextDNS config ID (`nextdns-id.txt`); Linux enforces NextDNS via `resolvectl` DoT when available. **Telos DNS stub:** when `dns-stub.enabled` or `dns-stub.port` is set, a local 127.0.0.1 UDP/TCP forwarder NXDOMAINs blocked hosts (allowlist wins) and nftables `inet telos_dns` redirects outbound :53 — host lists become **Enforced** only if stub bind + nft succeed; otherwise Failed/PreferenceOnly honestly; Windows/macOS PreferenceOnly. |
| **VOS-3** | **Partial (in tree)** | **App runtime MVP:** Flatpak sandbox tiers (Host / Vault FS / Net-isolated / Standard) + common permission overrides via `flatpak override --user` when Flatpak is present (Store permissions pane); degrades gracefully without Flatpak. `telos://` deep-link parser/dispatch into Telos virtual apps, Files, Media, and Kickoff search (`--open` / URI argv); Linux `x-scheme-handler/telos` registration (+ Windows HKCU URL protocol best-effort). **Winget/scoop** Store adapters on Windows (PATH detect, list/search/install with confirm; PreferenceOnly/unavailable on Linux/macOS). **Portal Camera/Mic** preference + `xdg-desktop-portal` Device/Camera ask when portal tools exist (Settings + Store permissions); otherwise PreferenceOnly. **Per-app netns** optional `unshare --net` / `ip netns exec` wrap for app-routing `deny` → isolated (and NetIsolated tier awareness); Flatpak keeps `--unshare=network` and never claims host netns without tools. |
| **VOS-4** | **Partial (in tree)** | `DesktopSessionSync` encrypted zip of `desktop.properties` + `~/.config/telos` (no WG private keys in logs); optional KeePassTL entry **Telos Sync** via kotpass; vaulted `DesktopStoredSyncKey` enables boot auto-import without a KeePass master-password prompt when the user has stored a sync key. **LAN pairing foundations:** `LanPairingServer` binds private/LAN addresses only, mints a short-lived code, QR/URI `telos-sync://pair?code=&host=&port=`; Android `DesktopLanPairClient` (Sync → Settings) handshakes for a pairing token and can fetch/post the AES zip4j session bundle. TLS optional later; mDNS optional (IP+code enough). Secrets never logged. |
| **VOS-5** | **Partial (in tree)** | Session backup/export in Network + Settings. **Full vault restore** (`DesktopVaultRestore`) from AES session bundle into vault HOME / `~/.config/telos` with confirmation UI (no WG private keys in logs/audit). **LUKS image restore** (`DesktopLuksImageRestore`): copy user-selected `telos_vault.img` into portable/vault image path with confirmation + SHA-256; requires vault locked; never mounts with a password. **Signed desktop updates** (`DesktopSignedUpdate` / Ed25519 `DesktopUpdateTrust`): verify `file://` or HTTPS manifest; `preferredManifestUrl` falls back to GitHub Releases latest asset `telos-desktop-update.manifest` (`DesktopGitHubReleasesChannel`, including documented Releases API lookup); stage under portable/vault temp, never auto-install. After confirmed stage, optional **restart helper** (`DesktopUpdateRestartHelper.prepareRestartAfterUpdate`) writes a pending marker + replace script and exits (in-place running JVM jar swap is best-effort). **Windows HKCU shell** (`WindowsShellIntegration`, `tools/windows/install-telos-shell.ps1`) optional. |
| **VOS-6** | **Partial (in tree)** | Secure clipboard history (vault-local, max 20, 5 min TTL, pin-until-lock; scrub IBAN/private/WG keys via `looksSensitive`; optional 0600 file under vault `~/.config/telos/opsec/`; **no cloud sync**; Super+V / panel glyph). Session vault + auto-clear timer for sensitive material; Linux clears system clipboard so untrusted apps cannot paste it; portable best-effort clear + UI. Append-only vault audit log (`~/.config/telos/opsec/audit.log`, 0600) for unlock, network policy, profile switch, panic. Attestation light: os-release / compositor / portable flag snapshot into the audit log, plus **TPM PCR 0/7 digest summary** when host `tpm2-tools` (`tpm2_pcrread` / `tpm2_getcap`) are present (`tpm=unavailable` otherwise, never fails unlock). Optional local `tpm2_quote` hex digest when `~/.config/telos/tpm/ak.handle` exists — **not remote attestation (RAP)**. **Vault-local file name index (opt-in):** AES-GCM under `.cache/telos/file-index`, vault/portable roots only (host profile only in Host Home), filenames/extensions for DesktopSearch/Files, no content upload. Viewer in Settings OpSec Helix card and Network → Status. Not shipped: remote attestation RAP. (Winget/scoop Store adapters live under VOS-3.) Stego FS Mode-B packaging remains separate transport obfuscation — not claimed as OpSec complete. |

Constraints that stay in force: no `:app:app` dependency on `:desktop-linux`; i18n keys from `:core:i18n` only; labwc is a **host package**, not bundled.

## Beyond the in-tree phases

Portable multi-host packaging, hardened hybrid PQ key wrapping, steganographic carrier transport productization, and a Windows shell/companion path are **not** additional unfinished P/H/S/W phases above. They are separate productization work. Do not describe them as shipped in user-facing docs until implemented.

**Stego FS (partial):** `StegoShardArrayManager.assembleAndOpen` / `assemblePrepared` write `telos-carriers.json`, attach dm-linear when available, otherwise assemble `stego_assembled.tvault`. Portable Data keeps carriers under `TelosPortableData/carriers/` (no host HOME traces). Full OpSec / deniability claims remain out of scope.
