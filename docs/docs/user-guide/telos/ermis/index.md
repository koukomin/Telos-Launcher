# Ermis

Ermis is a native Telos mail client, with an inbox inspired by Gmail and an IMAP/SMTP workflow inspired by FairEmail. It does not open a webmail provider to read or send mail.

## Connect an account

Open **Mail accounts → Add account**. Enter your email address, password (or provider app password), IMAP server and SMTP server. The username defaults to your email address. IMAP uses verified TLS, normally port 993. SMTP supports implicit TLS (normally 465), or required STARTTLS (normally 587). Both servers are verified before the account is saved. Invalid certificates and plaintext connections are not accepted.

Gmail supports an app password and an optional **Google / microG sign-in** button. This opens Android's account chooser and requests the selected authenticator's mail-access token with user consent. It works only when that installed authenticator grants the requested mail scope to Telos; it is not a bundled Google OAuth client or a guarantee that Google will approve access. If the provider refuses or requests unsupported configuration, use an app password. OAuth accounts use XOAUTH2, and background checks request refreshed tokens from the authenticator; tokens are not saved in the mail vault. Credentials are encrypted with an Android Keystore key. Removing an account removes its local credentials and mail cache, not its messages on the server.

## Read and send

Use **All accounts** or an account chip to filter the inbox. Search matches cached sender, subject and preview text. Starred mail has a separate filter. **Sync** checks the server; periodic checks run through Android WorkManager and can be delayed by battery restrictions. Notifications require Android notification permission.

Open a message to read its text, reply, save a note or save an attachment using the Android document picker. A formatted HTML view preserves passive tables, headings, lists and links, with a plain-text toggle. Scripts, forms, styling supplied by the sender and images are stripped; the local renderer independently blocks all network/resource requests. Links open in the browser only after a user tap. Large HTML falls back to plain text; formatted HTML is limited to 200,000 characters and is not kept in the disk mail cache. MIME depth, part count and body sizes are bounded. Opening a message also enforces a cumulative 24 MB raw multipart parsing budget across nested parts, so unusually large or deeply nested messages may be refused before their attachments can be listed. Saving an attachment uses the same selected MIME structure that produced the attachment list. The client keeps at most 1,000 cached messages, with the current folder showing its latest 150 messages. This is not a complete offline archive. Search filters cached sender, subject and preview. Search recent mail on server searches sender and subject among the latest 5,000 messages in the selected account/folder and returns at most 100 matches; it is explicitly not an unbounded whole-mailbox or body search. Notes are stored locally; Gmail accounts also synchronize note sidecars in the Ermis-Notes folder, keyed by Message-ID. Conversation grouping uses Message-ID, In-Reply-To and References within each account, rather than grouping unrelated mail with the same subject. Open the conversation count to choose among cached replies in a scrolling list. Choose an account and open Folders to browse existing selectable IMAP folders/labels, then select one to synchronize it. All accounts shows Inbox only. Folder roles come from server SPECIAL-USE metadata or conservative exact-name fallbacks; unmatched localized folders remain selectable by name. Folder creation/renaming and multi-label editing are not implemented.

**Compose** selects the sending account and accepts To, Cc and Bcc recipients, a subject, message and file attachments. Bcc recipients are included in the SMTP envelope without disclosing their addresses in the transmitted message headers. The file picker can access document providers, including compatible cloud storage providers. Telos Files private connections are not automatically document providers. For large files, upload separately and paste the sharing link; Ermis does not silently upload attachments to a third party. A send action is explicit and reports server failures; a failed request is never automatically resent. Each outgoing message is limited to 20 MB of attachments in total and 15 MB per file. SMTP success is reported separately from a failed Sent-folder copy, so the user is not told to resend an already sent message.

## Layout and device contacts

Ermis keeps a lightly translucent background with its own contrasting mail surfaces, so wallpaper cannot make text fields or message cards disappear. Search stays at the top; the floating Compose button opens a full-screen editor. Reading also uses a full-screen page. Both pages scroll with large fonts and keep navigation/actions outside the scrolling message, with keyboard and system-bar insets.

In Compose, tap the person icon beside To to choose an email address from Android contacts, including contacts from synchronized device accounts. Only the address selected by you is read; this picker does not require broad address-book access. Contacts without email addresses are not offered. Typed recipients remain available if the device has no compatible picker.

For an existing Google/microG account, open Mail accounts and select Google / microG sign-in again to grant consent anew. Expired OAuth credentials are invalidated and refreshed once during connection; password failures and sending are never automatically retried. Connection errors identify the IMAP or SMTP host and port without exposing credentials or raw server responses.

## Reply, forward and move

Reply uses Reply-To when available. Reply all additionally copies original To/Cc recipients, removes all configured sending identities, and deduplicates across To and Cc. Hidden recipients are never added. Forward opens a new composition with the message text and the original message attached as `forwarded-message.eml`, preserving its original attachments. The original is read with a 15 MB raw-byte limit before SMTP; its outer Bcc/Resent-Bcc headers are removed. Forward source metadata is retained in saved drafts, and UIDVALIDITY is checked before reading the source to avoid forwarding a different message after a server reset. The user may remove the original attachment before sending.

Move to folder chooses another existing folder within the same account and asks for confirmation. Archive, trash and spam shortcuts appear when a corresponding server folder is recognized; archive may use a recognized All Mail folder. There is no permanent-delete action. Native IMAP MOVE is preferred; fallback COPY must succeed before the source is flagged Deleted. UIDPLUS expunges only the selected message. Without UIDPLUS, the source remains flagged for deletion until the server or another client removes it; Ermis never broadly expunges unrelated messages. IMAP UIDs, validity and conversation grouping are scoped to account and folder.

## Local drafts

Use the Save icon in Compose to keep a draft in the encrypted local vault. The Drafts filter opens saved drafts for editing or deletion. Closing an edited composition asks whether to save, discard or continue editing. Drafts support incomplete recipient text, but sending validates every recipient and header. Up to 25 drafts are stored, with a 200 KB UTF-8 message-body limit and a 4 MB total draft budget; limits reject the operation instead of silently removing older work.

Draft attachments retain Android document-read permission. Providers that refuse persistent access may be used for immediate sending, but the draft cannot be saved with those attachments. If an attachment is removed or permission is revoked, sending fails before SMTP rather than sending an incomplete message. Drafts are local and are not yet synchronized to the Gmail Drafts folder. Saving is explicit; unfinished unsaved compositions are not a guaranteed process-death backup.

## Gmail feature coverage

The current client is not feature-complete with Gmail. It has native multi-account inboxes, conversation grouping, stars, cached search, reply/send, attachments, local notes and periodic notifications. Creating/renaming folders, editing multiple Gmail labels, whole-mailbox/body search, remote images and sender CSS, server-synchronized drafts, scheduled send, snooze and Gmail category/smart features still need implementation. Existing-folder browsing, safe move/archive/trash/spam, bounded recent server search, passive HTML, reply-all and original-message forwarding are implemented. Google/microG account access also depends on provider approval; the presence of microG alone does not guarantee mail scope access. These limitations must not be presented as completed Gmail parity.
